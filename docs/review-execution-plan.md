## 1. 执行原则与交付口径

在当前 `dev` 基础上切独立功能分支，按小批次实施。每个提交满足 `type(scope): message`，不创建新的两父合并提交；完成实际验证后，feature→dev→main 线性集成，按用户既有要求同步 GitHub/Gitee。先检查远端与工作树，不覆盖用户未提交改动，不重写历史。

每项任务先把本报告的失败行为放入正式测试或真实契约验收，再做最小修复。以下探针是审查证据，不应直接复制其 spy/H2/替身为“真实生产验收”：正式测试要覆盖修复相关的鉴权、持久化、事务副作用与实际调用入口。

遵守项目 AGENTS、原生 wl-skills-bd 入口和 Robot 映射。任务真实 notice 要包含包版本、路由/规则、目标、runId、待验项；同一后续用户整改任务跨批次、适用包复用同一runId，完成后提交原始validate/review/status。独立新用户任务才建立新记录，不能借用本轮failed审查收据伪造整改通过。不要套JH4J、平台响应码/Java8模板，不安装未使用的兄弟包。

涉及Admin的1B/批次3修改，重新遵守[Admin AGENTS](https://github.com/ChenyCHENYU/Robot_Admin/blob/2cb90509edd13b57595e7425813a992c842f2d8e/AGENTS.md)、[完整指南](https://github.com/ChenyCHENYU/Robot_Admin/blob/2cb90509edd13b57595e7425813a992c842f2d8e/.github/copilot-instructions.md)及其原生`.github/skills/`流程。该仓库当前没有安装PC Kit，不自动安装Kit，也不将Cloud的BD检查套用成前端门。Admin使用Bun及自身检查，两仓分别记录SHA和退出码。

必须保留的边界：

- 有效角色共享事实、永久操作者授予上界、精确role_button、公司成员归属、SQL数据范围与主体即时撤销。
- 写命令的业务/绑定/成功审计/DB epoch/Outbox同事务；Redis/HTTP在数据库事务外；失败不留成功副作用。
- 单刷新族CAS、一次性ticket、旧access/refresh拒绝、注销竞争与跨设备隔离；不通过放开重放换可用性。
- 已发布V1–V10迁移checksum不变。新增迁移同时验新库/升级库，不全局改MP字段为ALWAYS。
- 完整native失败原始证据、真实CI回执、未验证项。新增缺陷不得无理由ignore或扩基线。

本计划不自行授权生产数据写入、现网故障注入或外部平台配置变更。实施者使用有相应授权的隔离环境，并将所有不能执行的验收如实留作未完成。

## 4. 批次1：明确可复现缺陷的最小修复

### 1A 菜单根级持久化（REV07）

范围：MenuService拓扑命令、SysMenu父级更新、相关Mapper/事务行为测试。

实现：对“移到根级/显式根级编辑”精确生成`parent_id=NULL`，在原树锁和资源CAS范围内核验；重新读取校验两侧兄弟排序和父级。不要改变所有DTO空值策略。

验收：子→根before/after、子→子、根→子、编辑空父节点、循环与有效路径冲突；数据库父级/排序/revision/路由树正确。旧版本、审计或Outbox注入失败时业务与成功副作用全部回滚。真实MySQL用例单列，H2绿不能替代它。

建议提交：`fix(menu): persist root moves with explicit parent clearing`。

### 1B 稳定全局路由身份（REV08）

范围：MenuQueryService、路由合同、Admin动态路由/KeepAlive配对。

实现：以稳定菜单ID生成动态路由name，规定静态命名空间和有效绝对path唯一规则；评估既有name存储/缓存兼容，不随名称或排序变化。

验收：A/index与B/index、驼峰化碰撞、静态重名、相对/绝对等价路径；真实router注册后两页均可resolve，浏览器访问/缓存实例不互换。撤权只删除该资源路由。测试必须使用项目实际Vue Router，不只断言字符串不重复。

建议提交：`fix(menu): use stable unique identities for dynamic routes`。

### 1C 密码与模型输出（REV03/04）

实现：一个共享、可直接测试的密码新写规则，覆盖Service与DTO；同时维护字符要求和UTF-8字节边界，拒绝超限，不截断。确认已有超长凭据兼容/重置方案后才调整登录/旧密码语义。字段排除仅影响日志输出，保留必要JSON合同。依赖兼容升级见5C。

验收：ASCII/中文/emoji及71/72/73字节、新建/编辑/本人改密/管理员重置、历史凭据、错误新密码无任何revision/安全版本/审计/Outbox变化；四模型及嵌套集合输出不含合成秘密，正常内部供给/JSON仍成功。

建议分两提交：`fix(security): enforce password byte limits at write boundaries`、`fix(security): redact credential fields from model output`。

### 1D 可空资料（REV09）

依赖0的Patch决定。字段省略保留、显式清空可辨识；只为允许清空字段生成SET NULL。核对共享账号修改限制和账号/成员revision。

验收：email/phone/department/remark等实际支持字段逐项测试省略/null/空串，重读数据库和VO，清空部门后的范围按已决定合同计算；失败不推进版本。不能通过全局ALWAYS把其他必填字段清空。

## 5. 批次2：权限和匿名入口、生产配置

### 2A 全局目录权威身份（REV01）

先确定平台身份事实，服务层统一应用目录策略，覆盖菜单/按钮/字典新增、修改、删除、移动与启停；公司普通管理员及临时超管不得改变全局授权语义。展示资料编辑使用窄DTO/用例；编码更名有影响范围与绑定迁移。

验收：真实方法鉴权与Service负例覆盖所有入口；普通目录编辑者、仅临时身份、跨公司写拒绝且DB/绑定/审计/epoch/Outbox不变；合法永久平台管理员成功；事务异常全回滚。测试以真实有效角色事实构造，不Mock为“已拥有全部权限”。

### 2B 生产启动与bootstrap（REV02）

新增明确生产模式校验：环境唯一身份、正式inner secret、必要配置加载、数据库/Redis、管理/API文档访问策略、迁移/运行账号。开发配置保留可用，但生产模式拒绝缺失和已知占位值；没有正式配置就不开放业务。

固定V2种子通过新增初始化状态/迁移与安全交付流程处理，不改历史checksum；处理历史管理员须先核对身份，不能直接删除真实账号。开发凭据在开放业务前必须不可用，并验证安全版本/旧会话撤销。

验收：无效配置启动失败且日志无秘密；合规local与生产合成配置启动成功；remote必要配置故障不能静默转local。匿名prometheus/管理/API文档按约定限制；保持默认gateway管理路由关闭。多环境同userId签发/刷新/注销与命名碰撞负例通过。

### 2C 实际请求体限制（REV05）

实现有界流式累计字节过滤/受控边缘硬限制，加服务独立body边界和认证字段限制。Reactive DataBuffer拒绝/取消时正确释放，不把全body无界聚合再检查。

验收：limit-1/limit/limit+1经Content-Length、chunked、HTTP2；超限413且未调用用户名RPC/BCrypt；无长度普通小body可用，取消/重复释放/内存预算与背压有证据。不要只加DTO Size或Tomcat表单maxPostSize就宣称JSON边界修复。

### 2D 失败门控与审计（REV06）

跨Auth共享、有界的账号/可信来源短窗口，具备恢复、容量和Redis故障策略；公开失败先统一未知/停用/启用错误密码语义。公司发现/凭据持有后的停用提示与Admin共同决定。

验收：两Auth实例、换IP、代理来源伪造、未知账号高基数、恶意锁号、窗口恢复/Redis故障；正常登录及失败事件均可审查且无密码/token/raw请求。指标标签不得用用户名/IP/事件ID作为无限维度。

## 6. 批次3：Admin合同与写命令闭环

### 3A 用户/角色版本合同（REV10）

同步列表/详情/表单的账号revision、成员revision、角色revision。状态/移出/重置/删除发送专用DTO所需字段。冲突提示重读，不隐式用最新版本自动重试；批量命令逐项保留版本和结果。

验收：两个真实浏览器客户端，A变更后B旧页面冲突；有效版本成功、缺失/负数拒绝、跨公司拒绝、旧会话撤销。机器合同和mock均采用remote相同规则。

### 3B 资源删除/move CAS（REV11）

菜单/按钮/字典删除与move必需expectedRevision，Controller/Service/原子CAS/Admin统一。资源CAS与树锁各保职责，现有关联引用保护保留。

验收：缺失/旧版本/双客户端编辑删除竞争；拒绝不解绑、不记成功、不推进epoch/Outbox；合法序列排序和子节点/按钮/字典引用一致。不能仅服务器读最新revision后更新，冒充客户端并发意图保护。

### 3C 临时授权与精准撤回（REV10）

依赖0的产品模型。沿当前按人角色模型则统一Admin userId/roleId/effectFrom/effectTo/reason与后端返回VO；新增当前公司有效授权revision精准撤销命令，支持未来未开始授权的撤回；永久授予上界、主体状态和时间窗口仍检查。

验收：Admin→Gateway→System创建→生效→接口/按钮/范围→提前撤回/自然过期；旧版本、未来授权撤回、跨公司、临时再委托负例；两System旧缓存拒绝权限。成功审计与epoch/Outbox同事务，失败不留成功。不能用停用整个人/角色代替撤销一条授权。

### 3D 治理读取、能力声明与首页（REV10）

逐项统一数据范围/约束/审计/成员VO字段与枚举，状态来自公司成员而非仅账号；定义账号/成员开停矩阵。对暂未实现的字段规则/约束明确能力状态；实现的保存要验证实际SQL/VO效果。确认无首页角色的合法落地行为，不附赠业务授权。

验收：真实remote页面创建/保存/重读/执行链；角色成员抽屉状态正确；无首页、有其他页/仅首页/无角色/撤回首页/公司切换组合；不能只MVC200或mock展示成功。

## 7. 批次4：真实MySQL引用竞争与成员部门迁移

### 4A 先验真，再修跨聚合引用竞争（REV12）

用当前目标MySQL隔离级别建立可控屏障，覆盖角色删除vs普通绑定/临时授权、成员移出vs临时授权。先记录实际SQL顺序/锁/提交与最终关联，再实施统一事实行锁、稳定多对象锁顺序、锁内重验与冲突语义。

验收最终无新提交的失效活跃关联；拒绝/回滚事务不留下成功审计或事件。授予先成功、随后移出撤销是合法序列，保留两笔成功记录；不要硬要求所有并发只留一个成功。保留Resolver失败关闭，死锁重试有界，关联/审计/epoch/Outbox同事务。H2与单对象CAS用例不能替代这个屏障验收。

### 4B 公司部门事实（REV13）

依产品决定，用成员主部门/关联表做Expand迁移。只回填能证明归属的部门，冲突明确登记；双读比较/单写切换/回滚窗口受控，不维护永久双主事实。

验收同账号A/B不同部门互不影响，非法/停用/祖先环/移出负例，账号与成员revision各自正确，历史数据回填可对账，新库/升级库均通过。发布V1不改，SQL迁移与代码切换兼容滚动升级。

## 8. 批次5：让持续门禁真实工作

### 5A Java质量与架构/覆盖率（REV15）

在父POM按Java17接实际Checkstyle、PMD7、SpotBugs、Spotless、JaCoCo，启用共同`verify`入口。老问题按有理由/范围的审查基线管理，新增阻断；不整仓格式化混入安全功能提交。

按BD14当前红线：Service类行覆盖≥70%、分支≥60%；Controller类行≥50%，不设分支统一阻断；CLASS粒度。DTO/Mapper/配置不设统一比例，但安全/装配行为仍须测。排除项说明理由，不能排除整个service包或用包平均掩盖未测类。

补Auth与System域内允许依赖/循环规则，用真实违反分层的测试样本证明门可失败。敏感配置扩展点验证零/重复/正确Bean实际容器装配。扩合同到菜单、治理、会话与inner；数据库合同按风险扩属性/表，执行结果回到统一入口。

### 5B BD适配与收据（REV16）

与包维护仓库独立小提交协作：Sa-Token/公开/inner入口识别，MP逻辑删除与隔离DDL边界，Lombok敏感字段，Robot分页/事实合同，Java17与禁用生成的profile，实际ArchUnit门关联。支持识别有负例：删除注解/拦截器、漏租户、输出秘密、分页超限必须失败。

修根输入快照忽略生成target/自身报告与预算可见性；保持真正扫描checkedSnapshot，不跳过业务文件。先固定构建，再检查/生成外部收据，最终同runId status不能因自身输出stale。原始74条保留，解释与整改分别记录；没有接入的J门不能伪造passed。

### 5C 支持版本与供应链（REV18）

确认Boot/Cloud/Alibaba兼容且仍有维护的GA组合；先用独立依赖分支编译、契约、全装配、MySQL升级、Sa-Token/Feign/Nacos/Gateway运行回归，再合入。不能单独升一个Security版本打破BOM，也不能不确认仓库可获取就填商业补丁。

补SBOM、实际漏洞/许可证扫描、例外到期与升级责任；记录扫描数据库时间和离线/网络失败。固定Maven wrapper/JDK运行策略，至少真实JDK17验证当前承诺；当前JDK21 release17绿不替代Java17运行。版本兼容注释按官方矩阵校准。

### 5D 真实CI与线性历史（REV17）

2026-10-14 文档复核已取得当前基线 verify job 的实际 annotation，确认因 GitHub 账号计费锁定未启动，见 [复核补充](review-2026-10-14.md#10-文档归档复核与-ci-补充)。由账号持有人处理后，对目标提交核对真实执行；其他 run 的失败另行诊断。实现新增范围 parent-count 拒绝两父提交，保留历史边界；commit 消息规范单独检查。测试包含正常 merge、伪装普通消息的两父 commit、合法线性与旧历史。

让当前SHA在目标CI真实执行JDK17、隔离MySQL升级、全部门禁并下载artifact；对main/dev配置真实检查和线性保护，用失败PR验证不可合入。内网CI可用同入口，但不能宣称GitHub/Gitee双方已经执行相同门。合入后核对两个remote的dev/main SHA；不force-push重写历史来通过门。

## 9. 批次6：认证响应时序与依赖预算

### 6A 轮换CAS后有界响应（REV14）

先记录Auth刷新/切换各阶段deadline。非关键同步审计改可靠有界投递边界，说明队列满/投递失败/宕机恢复；若审计升级为必须成功前提，先定义可关联CAS结果的幂等提交事件/状态和故障恢复合同。不得将成功recordLogin简单移到CAS前，竞争输家和失败操作不能留下成功审计。CAS后旧索引清理限制总预算，不无限等待。

验收真实Gateway前提：慢账号供给、慢审计、CAS后Redis清理超时、客户端断开/网关提前超时；记录CAS点与响应/审计时间、新旧凭据可用性。保留单胜CAS、注销不复活、重放拒绝、跨设备隔离。定义最终网络丢响应的重新认证或受审恢复合同，不能恢复旧refresh让它任意重试。

### 6B 时间与数据库预算（REV21）

Outbox重试优先用DB当前时间加相对退避，或经验证的统一Clock/DB session合同；不要无评审把所有Admin DATETIME格式改UTC。driver connect/socket、query、事务/锁等待与worker总预算协同，连接获取timeout单独保留。

验收JVM/DB正负偏差和不同zone、重启，退避到期区间正确；隔离代理网络黑洞、长SQL、锁等待后请求/worker在预算内失败，连接可回收、事务已回滚、后续任务可恢复。不能只取消Future后留下DB执行。

## 10. 批次7：性能、故障与未来扩展

### 7A 测量后做读取优化（REV19）

固定公司数/成员/角色/资源/历史规模与冷暖缓存分布，统计每请求SQL/Redis/RPC、阶段延迟、DB池等待、堆/响应大小、p95/p99和撤销延迟。先交基线，再优化请求内主体复用/精确context、大列表分页、树分组迭代；写事务安全事实重验保留。

全局epoch评估多公司混合读写控制行锁等待与跨公司失效；若分层，保留全局资源改动、跨公司账号撤销、迟到回填和期限围栏。交同数据同负载前后对比，不提供未经测量的“提升50%”。

### 7B Outbox容量/索引/留存（REV20）

两System同时启动、指定断网时长/入队速率、大完成历史与大pending，测恢复曲线、重复发送比例、总DB/Redis次数、rows examined/排序/慢查询。以结果选择租约/分片/有界并发/索引/快照频率；保留revision结果围栏、事务外发送、Lua单调和字典删除幂等。

毒事件可审查隔离、告警与修复重放；租约worker宕机与迟到ACK有恢复。完成历史分批归档/恢复/对账，pending不按创建时间删，重放审计保留。归档与人工重放并发时，锁内或以完成状态+delivery_revision原子重查，不得按旧完成快照删除已重放成pending的事件。不要仅给所有worker加全局锁，也不要只pending归零宣称长期容量通过。

### 7C 当前制品运行、HA与运维（REV22/24）

真实启动Gateway/Auth/两System并记录合成配置摘要，不输出凭据。验登录公司激活、菜单/按钮/范围、写命令、撤权与旧会话；MySQL新库/升级库和打包Mapper验收绑定当前制品。

Redis短断/恢复、重复消费、迟到通知、worker重启、旧缓存回填、旧Redis快照恢复，以及目标HA主从切换/DB恢复分别验证。按声明的撤销持久性目标明确断言已注销族、已轮换旧access/refresh不复活，其他合法设备不误撤销；健康UP或单次权限403不能代替逐族验证。安全依赖故障维持fail-closed；以冗余/恢复改善可用性，不取消主体核验。

加worker轮次/扫描/最后完成、身份阶段、低基数业务结果、安全异常分类；HTTP200的失败Result必须被业务指标识别。实际看板/告警触发、接收/恢复、snapshot过旧/采集缺失、滚动发布/drain/readiness、备份恢复/RTO/RPO都有证据。对外与普通日志继续脱敏，受限诊断不能原样记录秘密。

### 7D 新服务准入与内部边界（REV23）

先登记System内部业务允许依赖，用架构门维护。新增服务必须明确数据owner、受众与独立服务身份、主体核验必需装配、凭据供给限制、租户/撤销/错误/版本契约、总deadline、事件幂等和迁移/运行证据。

当前Auth/System主体核验已装配；测试未来服务零/错误/重复核验Bean启动行为，防止空provider静默接受。只有实际独立需求才拆文件、通知或业务域；角色/绑定/成功审计/epoch/Outbox继续一个本地事务。不能把“拆更多服务”列为本轮质量完成标志。

## 11. 每批回传清单与最终完成标准

| 材料 | 要求 |

现有常规入口是 `scripts/verify.sh`、`bun run test:tooling`、`bun run check:commits`、`bun run check:bd`、`bun run bd check --target . --json`。真实MySQL升级使用已有 `scripts/verify.sh --mysql-upgrade` 及专用隔离环境变量；实际Java质量profile落地后并入同入口。不要用`--help`试运行BD子命令，0.37.0部分命令会忽略help实际执行，应读对应CLI源码/文档确认参数。

Admin当前实际统一入口是`bun run verify`；相关浏览器回归使用`bun run test:e2e`。两者都不能代替真实remote链路：用当前Cloud制品做Admin→Gateway→Auth/System页面验收，明确mock/remote、配置与凭据来源并保留结果。本轮没有执行Admin全量verify或浏览器E2E，未来报告不得将本轮Vue Router/MVC内存探针列为它们的成功结果。

本轮审查的最终status是failed/fresh，不能作为未来整改完成凭证。每批只有**问题行为修复 + 必要鉴权/事务负例 + 真实适用检查 + 对应运行验收 + 可审查证据**齐备才标完成。生产闭环还需要批次7的目标环境证据；本地构建绿、0新增基线、mock页面成功或测试数量增长都不足以代替它。
