# 认证会话生命周期

本实现保留 `/auth/login`、`/auth/context/activate`、`/auth/context/switch`、`/auth/refresh-token` 与 `/auth/logout` 的公开请求/响应字段。`token`、`refreshToken` 和 `loginTicket` 仍为不透明字符串；客户端不能解释内部状态或拼接公司身份。

## 会话归属

公司、成员上下文和角色快照保存在 Sa-Token **token Session**，账户 Session 不保存这些业务属性。相同 userId 的两个 token 可以分别保持公司 A/B；切换公司只轮换当前设备的 access/refresh，其他设备保持原上下文。

每次登录建立一个随机刷新族。`robot:{env}:auth:family:{familyId}` 是该设备的权威状态，包含 userId、contextId、账号与成员安全版本、当前 access 原文及摘要、refresh 摘要、登录时凭据指纹。access 原文只用于调用 Sa-Token 注销接口，绝不进入响应之外的日志；refresh 原文仅在生成时返回，Redis key/value 都保存其 SHA-256 摘要。

刷新族、当前 refresh 摘要索引、当前 access 摘要索引均携带精确 7 天 TTL，不附加业务缓存抖动。正常轮换会删除旧索引；删除失败的残留索引只能活到原 TTL，且旧摘要无法通过当前族状态校验。登录票据使用 SecureRandom 生成 32 字节，精确 5 分钟 TTL，索引也是 SHA-256 摘要；票据内容绑定 userId、账号安全版本及登录时的密码摘要指纹。

## 提交点与故障行为

1. refresh 先读取当前族状态，再远程复验账号、有效公司成员上下文、两个安全版本及密码指纹。临时 RPC 失败不消费旧凭据，可重试；停用/成员失效/改密等确定失效对仍匹配原快照的族执行 CAS 撤销。过时的失败请求不能撤销已经成功切换的后继状态，撤销标记携带精确 7 天 TTL。
2. 签发候选 access，建立候选摘要索引后，使用单 key Redis Lua CAS 比较完整旧状态并替换为新状态。两实例竞争只能有一个提交者；输家撤销自己的候选 token，不能撤销赢家或恢复旧族。
3. CAS 提交后清理旧 token/索引。请求态族验证要求 access 摘要与当前族一致，因此 Sa 映射清理失败也不会继续接受旧 access。
4. CAS 响应丢失时，对自己的候选状态执行 CAS 撤销标记并清理候选 token，绝不以 SET 恢复旧状态。此次刷新可能要求用户重新登录；不承诺网络故障下无损重试或返回相同新 refresh。
5. loginTicket 先完成下游复验和公司选择，再以单 key Lua 原子读取并删除；仅取到该票据的请求可签发。下游故障保留票据；最终消费后进程中断/签发失败不会重建票据，用户需重新登录。

这里使用的 Redis SETNX 是新族随机身份的冲突保护，不是分布式锁。刷新与注销依赖 CAS/原子消费，不依赖 JVM synchronized，也不依赖会过期的短租约锁。

## 注销与请求态验证

`POST /auth/logout` 继续接收原有 Bearer 头，不要求新增请求体。即使当前 access 已自然过期，持有其原文仍可经摘要索引定位并删除刷新族。无 token 拒绝；已经注销的 token 幂等返回。旧 access 在完成轮换、索引清理后不能注销后继族。

注销的单 key 原子删除是提交点：若刷新先提交，则注销删除后继状态；若注销先删除，则候选刷新 CAS 失败。可能出现刷新响应晚于注销返回，但其中 token 已无效，不能恢复族。已在验证前通过的在途业务请求不承诺被中途取消。

以上原子顺序以 Redis 主节点状态不回退为前提。Redis 异步复制故障切换或恢复旧快照，可能恢复仅保存在 Redis 的注销状态；此实现没有数据库持久化的逐族注销记录。账号/成员安全版本由数据库兜底，恢复旧 Redis 快照不能恢复已改变版本的身份。生产 HA 验收必须包含注销后立即切换主节点、恢复旧快照及持久化丢失场景；不能把单主节点并发测试当成撤销持久性证明。

所有需要登录的请求验证 Sa-Token 登录态、token Session 的 familyId 对应状态、access 摘要及主体/成员/版本快照一致性。公开 login/activate/refresh/logout 由其业务流程验证持有凭据，避免过期 access 阻断合法刷新/注销。系统服务通过 `SessionSubjectVerifier` 对数据库复验账号、成员、公司、安全版本与当前密码指纹；认证服务通过同一扩展接口和服务身份 RPC 复验，因此聚合菜单等受保护读取也不能使用旧版本 access。临时 RPC 失败以系统暂不可用阻断本次请求，保留族状态，健康重试无需重新签发；确定失效由请求拦截器返回未登录。账号或成员停用后再启用，旧安全版本仍失效，不会使旧会话恢复。切换会先复验当前族的原成员上下文，再绑定目标上下文的当前版本，不能借切换绕过原成员撤销。内部 RPC 缺少版本字段时失败关闭，不把 null 默认为 0。

## 升级与验证范围

旧版账户 Session、明文 refresh payload 与只存 userId 的 loginTicket 不兼容新状态格式，部署升级后必须要求现有客户端重新登录。客户端仍应合并同设备并行刷新；服务端对重复已消费凭据明确拒绝，不提供自动重试签发新族。

本轮行为测试使用真实 Sa-Token 内存 DAO + Servlet request 验证 token Session 隔离，使用两个认证组件实例及共享原子内存存储验证 CAS/注销竞争、过期、RPC 故障、改密和候选补偿。Redis Lua 的真实主从故障、cluster、跨实例 HTTP、Nacos 与生产网络尚需独立基础设施集成验收；单元测试不替代这些运行证据。
