# 系统域授权与公司成员契约

本轮系统域把当前公司成员关系作为用户管理边界。平台账号 `sys_user` 可以属于多个公司；公司管理员不能通过移出或停用成员删除、停用其他公司的同一账号。公司上下文来自认证身份，客户端的公司字段不能扩大查询或写入范围。

## 有效授权

有效授权要求平台账号、租户、公司及唯一公司成员均启用且未删除。角色来自该用户在当前公司的普通绑定，以及满足 `effectFrom <= 当前时刻 < effectTo` 的临时授权；角色本身必须启用且未删除。只有有效绑定中的 `SUPER_ADMIN` 才具有超级管理员权限。缓存必须在下一临时授权生效或到期时重新求权，时间遵循现有服务器时区和 `LocalDateTime` 数据合同。

普通操作者只能授予自身永久启用角色拥有的资源和数据范围，不能修改自己持有角色，不能创建或授予超级管理员角色。授权管理的超级管理员例外同样只能来自永久绑定。临时角色可以在有效时间窗内用于已授权的业务请求，但不能放大为永久授权或更长的下游临时授权。角色新增、编辑、单独绑定权限、成员绑定角色和临时授权使用同一上界。管理用户的编辑、移出、停用、重新启用、重置密码还会检查目标用户的角色上界，包括停用角色与未到期的未来临时授权，避免先停用后绕过检查。普通操作者管理自己的资料与密码应使用本人接口，修改密码需要原密码。

菜单与按钮独立绑定。页面菜单授权不自动附赠该页全部按钮；按钮授权不自动授予页面权限码。为了导航可用而补入的父级菜单不提供页面权限码。菜单与按钮均需启用且未删除，按钮还要求父菜单有效。权限目录中的 `id` 是实际菜单或按钮 ID，不能以权限码作为绑定 ID。

## 客户端版本和关联写入

Robot Admin 需要读取详情版本并随写命令提交；旧客户端缺少必填版本的请求会被拒绝，不能静默覆盖其他管理员的修改。

| 命令 | 必须携带的字段 | 空值语义 |
| --- | --- | --- |
| 角色编辑 | `revision` | 未提交权限字段保留现有绑定；`permissionIds: []` 清空绑定 |
| `PUT /sys/roles/{id}/permissions` | `revision`、`permissionIds` | `permissionIds` 不能为 null；空数组清空绑定 |
| 成员编辑或重绑角色 | `membershipRevision` | `roleIds` 不提交保留绑定；`roleIds: []` 清空当前公司绑定 |
| 成员编辑同时修改账号资料或密码 | `membershipRevision`、`revision` | 编辑密码留空表示不改密码 |
| 成员启停、移出 | `expectedRevision` = `membershipRevision` | 启停用专用DTO；移出版本放query，缺失/负值/冲突拒绝 |
| 管理员重置密码 | `expectedRevision` = 账号版本；`expectedMembershipRevision` = 成员版本 | 专用DTO，两个CAS、凭据安全版本、审计及Outbox同事务 |
| 角色删除 | query `expectedRevision` = 角色版本 | 引用/公司/权限/版本共同校验，关联与审计整体事务 |

角色详情返回 `revision`、`permissionIds`、`menuIds`、`buttonIds`。用户详情返回账号 `revision`、公司成员 `membershipRevision` 和当前公司的 `roleIds`。关联修改先比较客户端版本，再执行父聚合乐观锁写入；受影响行数不是 1 时返回并发冲突，不继续重绑关联或记录成功事件。并发冲突后客户端应重新读取详情，再由用户决定是否重试。

角色表单兼容 `name/code/sort/description`，角色读结果也返回这些只读别名及 `createTime/updateTime`；`description` 和 `remark` 目前指向同一备注字段。用户表单及读结果兼容 `deptId`，用户读结果兼容 `createTime/updateTime`。角色权限既支持统一 `permissionIds`，也支持旧 `menuIds` 加 `buttonIds`，二者不能同时提交。每批资源最多 500 项，资源 ID 不得为空、重复、超长、失效或跨公司。

## 公司成员与共享账号

用户列表只返回当前公司未删除成员，`status` 表示成员状态。停用和重新启用只修改当前公司成员状态。移出成员撤销本公司的普通和临时授权，并保留平台账号及其他公司成员关系。内置管理员和禁止停用或移出自身的规则继续保留。

目前昵称、邮箱、电话、部门及密码仍保存在平台账号表。公司管理员只能修改由本公司独占的账号资料及密码；属于多个公司的账号资料和密码由本人接口管理，公司成员编辑可以保留原有平台资料并调整本公司授权。不能把现有全局部门字段伪装为各公司的部门。将部门或其他档案迁移到成员关系需要单独的数据模型和迁移方案。

成员停用或移出、账号密码变化会推进独立的安全版本；重新启用不倒退版本，因此停用前或改密前的旧会话不能恢复。普通资料变更仍使用乐观锁 `revision`，不会因此踢掉设备。

## 数据范围的当前限制

`dataScope` 支持 `self/department/department_below/all` 的配置上界。新配置的 `custom` 因缺少自定义范围模型而被拒绝；未提交数据范围的编辑不会改写已有旧值。

用户列表与用户详情已在 SQL 和目标校验中消费当前有效角色范围：`self` 只可读本人，`department` 只可读本人及本部门，`department_below` 可读本人及合法部门子树，`all` 仍只可读当前公司成员。本人全局部门缺失、停用、属于其他公司、祖先失效或出现环时，部门范围退回本人。没有有效角色或只有未实现的 `custom` 时拒绝用户读请求。本人资料/改密入口和角色绑定结构查询不受该用户读侧筛选阻断。

该实现仅覆盖用户读取，不是通用业务查询数据权限引擎，尚无字段可见、可编辑及脱敏模型。权限约束配置表目前也只提供读取，互斥、继承和二次确认没有规则执行器；基础自授与授权上界由服务中的固定安全规则执行。业务与治理模型接入前必须实现并测试实际查询、约束和字段处理，不能把显示范围或公司租户拦截器当作通用数据权限已经执行的证明。

## 验证范围

本轮本地测试使用模拟 Mapper、固定时间及本地 H2，覆盖授权事实、公司边界、版本冲突、授权上界、共享成员行为及精确菜单/按钮。H2 用例验证实际 MyBatis Plus 乐观锁、成员移出的受限 SQL、安全版本及审计失败后的事务回滚。没有连接外部数据库、Redis 或 Nacos；MySQL 迁移、生产方言 SQL、缓存投递重试与多节点并发仍需在隔离环境验收。
